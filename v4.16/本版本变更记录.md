# v4.16 本版本变更记录

## 版本定位

- 版本：v4.16
- 日期：2026-08-13
- 文件：全能去广告修复版-Shadowrocket-v4.16.sgmodule
- 基线：v4.15/全能去广告修复版-Shadowrocket-v4.15.sgmodule
- 用户反馈：v4.15 已经可以进入闪动校园，但出现开屏广告。
- 目的：在保留 v4.15 启动稳定性的基础上，小步处理开屏广告，不回退到会闪退的拦截方式。

## 判断依据

- v4.15 为了验证启动稳定，加入了 USER-AGENT,ShanDong*,DIRECT，并且保留了 shunchangzhixing.com 的直连。
- 新反馈说明稳定性已经改善，因此可以开始逐条回收广告放行。
- 之前日志显示开屏广告链路中有 http://ad.shunchangzhixing.com/getAd/877542，并且 v4.7 没广告时曾对 getAd 返回空数组。
- v4.14/v4.15 的稳定修复点是 base/infoConfig/checkCd 和各广告 SDK 初始化链路，v4.16 不拦截这些启动配置接口。

## 本版本更改

- 禁用过宽的整 App 直连：
  - USER-AGENT,ShanDong*,DIRECT 改为注释。
- 保留 v4.15 中所有明确的启动 SDK 直连白名单，避免回到闪退。
- 补充显式直连：
  - DOMAIN-SUFFIX,ctobsnssdk.com,DIRECT
  - 这是为了替代原本被 USER-AGENT,ShanDong*,DIRECT 覆盖的启动期字节日志请求。
- 在 [Map Local] 顶部恢复闪动校园 getAd 空数据：
  - http://ad.shunchangzhixing.com/getAd
  - https?://ad.shunchangzhixing.com/getAd
- 不处理 ad.shunchangzhixing.com/base、admin.hzjizhun.cn/infoConfig、checkCd、gromore 配置等启动稳定相关接口。

## 风险说明

- v4.16 是小步收紧：只动开屏广告最明显的 getAd，不直接封禁广告 SDK。
- 如果开屏广告消失且仍稳定，下一版再继续收紧其它广告展示链路。
- 如果重新闪退，说明 getAd 返回空数组仍会影响当前版本启动，需要退回 v4.15 后改用别的广告入口处理。

## 验证项目

- 已确认 v4.16 保留 v4.15 启动 SDK 白名单。
- 已确认 USER-AGENT,ShanDong*,DIRECT 已被注释，不再整 App 放行。
- 已确认 getAd 空数据 Map Local 位于 [Map Local] 顶部。
- 已确认原始 PacketTunnel 日志继续被 .gitignore 忽略，不上传 GitHub。
