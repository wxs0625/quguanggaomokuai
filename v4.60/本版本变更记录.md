# v4.60 本版本变更记录

日期：2026-08-25
文件：全能去广告精简范围恢复版-Shadowrocket-v4.60.sgmodule

## 问题背景

闲鱼与酷安"第一次冷启动开屏广告"在 v4.55–v4.59 连续五个版本中反复修不好。
本版本通过 **2026-08-24 16:36 的真实流量日志**（`proxy-2026-08-24-163617.db`，75 条闲鱼启动记录）完成了根因取证，不再猜测。

## 根因（已由流量日志证实）

### 闲鱼
- 日志中闲鱼主 API 全部命中外部分流规则集：`DOMAIN-SUFFIX,goofish.com,DIRECT`。
- **DIRECT 流量直连服务器，根本不经过代理节点** → MITM 无法解密 HTTPS → 所有针对 `acs.m.goofish.com` 的 URL Rewrite / Map Local / Body Rewrite / Script 规则**全部静默失效**。
- 日志同时显示模块自身的明文 HTTP 规则（`amdc/mobileDispatch` REJECT）正常触发 12 次，证明：
  - 模块规则优先级没有问题（模块 [Rule] 先于用户/外部分流规则匹配）；
  - 问题纯粹是"该走代理的域名被外部规则集直连了"。
- v4.59 只移除了模块自身的 DIRECT 排除，无法对抗**外部分流规则集**的 DIRECT，所以仍然无效。
- 这也解释了"第一次有广告、再次启动就没有"：冷启动实时拉取广告（走直连，拦不住），之后的启动用缓存配置（被已拦截的响应影响）。

### 酷安
- 酷安的拦截规则在历次精简中被整体删除：[URL Rewrite] / [Body Rewrite] / [Script] 均无 coolapk 条目，[MITM] 也无 coolapk 主机。
- 即使流量走代理，也没有任何规则处理酷安广告。

## 修复内容

### 1. [Rule] 顶部新增强制代理覆盖（核心修复）
```
DOMAIN,acs.m.goofish.com,PROXY
DOMAIN,g-acs.m.goofish.com,PROXY
DOMAIN-SUFFIX,coolapk.com,PROXY
```
- 模块 [Rule] 优先于用户/外部分流规则匹配（流量日志已证实），因此这三条规则会覆盖外部分流规则集的 DIRECT，强制让闲鱼/酷安广告接口的 HTTPS 走代理，使 MITM 能够解密并应用全部净化规则。
- 只覆盖去广告所需的最小域名集（`acs.m.goofish.com`、`g-acs.m.goofish.com`、`coolapk.com`），闲鱼其余功能域名（taobao.com、alicdn.com 等）仍走原有直连分流，不影响正常使用与速度。

### 2. 恢复酷安净化规则（来源 v4.0 上游，逐字恢复）
- [URL Rewrite] 1 条：酷安热搜 `type=hotSearch` 拦截。
- [Body Rewrite] 6 条：`feed/detail`、`feed/replyList`、`main/dataList`、`page/dataList`、`main/indexV8`、`main/init` 的推广卡片/热搜净化。
- [Script] 4 条：`酷安`、`酷安 #2`、`酷安 #3`（fmz200 coolapk.js）与 `酷安URL重定向`。

### 3. [MITM] 补充酷安主机
- 追加 `api.coolapk.com, www.coolapk.com`，使酷安的 HTTPS 流量可被上述规则处理。
- 闲鱼的 `acs.m.goofish.com`、`g-acs.m.goofish.com` 本就已在列表中（此前因直连而未生效）。

## 保留项（未改动）

- 闲鱼全套净化规则（7 条 URL Rewrite、6 条 Map Local、40+ 条 Body Rewrite、7 个 goofish.js 脚本）保持不变，本次只是让它们"有机会被执行"。
