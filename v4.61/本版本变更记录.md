# 全能去广告精简范围恢复版 v4.61 变更记录

- 基线版本：v4.60
- 发布日期：2026-08-28
- 问题现象：用户反馈安装 v4.60 后，闲鱼、哔哩哔哩等多个 App 的**开屏广告重新出现**（信息流等其他广告仍正常屏蔽）。

## 根因分析

逐项排查后确认：

1. **模块文件结构完好**：6 个区块完整，`PROTOCOL,QUIC,REJECT` 存在，`[MITM]` 段与 v4.59 逐字节一致。
2. **开屏规则一条未丢**：v4.60 与 v4.57 的开屏规则、哔哩哔哩规则逐行完全一致；`acs.m.goofish.com`、`g-acs.m.goofish.com`、`app.bilibili.com`、`acs.m.taobao.com` 均在 `[MITM]` hostname 列表中。
3. **无排除项误伤**：347 个主机中 47 个 `-` 排除项全部为新浪/酷安/微博/友盟系，通配符不覆盖闲鱼/淘宝/B站。

定位到最可疑的结构性隐患：**`[MITM]` hostname 是一行 6,658 字符、347 个域名的超长列表，而受影响的关键开屏域名全部位于列表尾部**：

| 域名 | 原字符位置（总长 6658） |
| --- | --- |
| `acs.m.goofish.com`（闲鱼开屏） | 5798（约 87% 处） |
| `g-acs.m.goofish.com` | 5817 |
| `app.bilibili.com`（B站开屏） | 6263（约 94% 处） |
| `bbs-api.miyoushe.com` | 6281 |
| `edith.xiaohongshu.com` | 5623 |

若 Shadowrocket 在合并/解析超长单行配置时存在截断或尾部丢弃，排在末尾的域名会失去 HTTPS 解密。这恰好解释"**依赖解密的重写/脚本类开屏拦截全部失效，而 [Rule] 层域名级拦截（信息流/横幅）不受影响**"的现象。

## 修复内容

### 1. 重排 [MITM] hostname 顺序（核心修复）

- 将被重写/脚本规则实际引用的 **255 个域名**移到列表最前面，并按规则中**首次出现的使用顺序**排列（最高频的接口域名靠前）；
- 其余 92 个未被引用的域名保持原相对顺序置于其后；
- **347 个域名一个不删、一个不增，集合完全等价**（已用脚本校验 `same_set=True`）。

重排后关键域名位置（0 基序号）：`app.bilibili.com`=1、`bbs-api.miyoushe.com`=2、`acs.m.taobao.com`=30、`mime.baidu.com`=26、`acs.m.goofish.com`=118、`g-acs.m.goofish.com`=119、`edith.xiaohongshu.com`=133、`app.zhuanzhuan.com`=137。

### 2. 哔哩哔哩开屏接口增加请求级兜底拦截

在 `[URL Rewrite]` 新增（与原有 Body Rewrite 双保险）：

```
^https:\/\/app\.bilibili\.com\/x\/v2\/splash\/(list|show|event\/list2)(?:\?.*)?$ - reject-dict
```

### 3. 闲鱼开屏接口增加前缀式兜底拦截

在 `[URL Rewrite]` 新增（覆盖 splash/splash.ads 全部变体与 g-acs 域名）：

```
^https?:\/\/(g-)?acs\.m\.goofish\.com\/gw\/mtop\.taobao\.idlecommerce\.splash - reject-dict
^https?:\/\/(g-)?acs\.m\.goofish\.com\/gw\/mtop\.taobao\.idle\.home\.splash - reject-dict
^https?:\/\/acs\.m\.taobao\.com\/gw\/mtop\.taobao\.idlecommerce\.splash - reject-dict
```

### 保持不变

- 全部原有规则（本次**零删减**），仅新增 4 条兜底 + 重排 hostname；
- `PROTOCOL,QUIC,REJECT`、闲鱼 `idle.home.welcome`、[Map Local] 开屏 mock 等。

## 预期效果

- 闲鱼、哔哩哔哩等 App 开屏广告重新被拦截；
- 信息流等其他广告过滤不受影响；
- 超长单行配置尾部解析丢失的风险被消除。
