# v4.61 本版本变更记录

日期：2026-08-26
文件：全能去广告精简范围恢复版-Shadowrocket-v4.61.sgmodule

## 问题背景

用户反馈：**很多软件第一次开屏有广告，后边再次启动就没有了**。
经确认回退到 v4.57 基线（v4.57 不含 v4.58/v4.59/v4.60 的后续改动），基于 v4.57 重新修复。

## 根因（沿用 v4.58 的分析）

"第一次有广告、再次启动没有"的机制：

1. 冷启动时 App 立即请求**广告SDK域名**（如穿山甲 `is.snssdk.com`、Tanx、Mintegral 等）获取开屏素材；
2. 这些请求走 HTTPS，而 URL Rewrite / Map Local / Script 都必须 **MITM 解密**才能处理；
3. 广告SDK域名大多不在 MITM hostname 列表中 → MITM 不解密 → 广告请求成功；
4. v4.57 的全局 QUIC 阻断 + URL-REGEX 兜底对 HTTPS 同样依赖 MITM → 仍有遗漏；
5. 第一次加载成功后 App 缓存配置，再次启动读缓存 → 广告消失（这正是"后边就没有了"的原因）。

**关键：需要一个不依赖 MITM、在路由层直接拒绝连接的方案。**

## 本次改动（基于 v4.57，仅一处）

### [Rule] 新增路由级广告SDK域名阻断块（53 条新规则）

自 v4.58/v4.59 移植，**已按 v4.57 现有规则逐条去重**（v4.57 基线本身已含大量广告域名规则，
其中 93 条候选规则已存在，只补充真正缺失的 53 条）。

`DOMAIN/DOMAIN-SUFFIX REJECT` 在**路由层**生效，不需要 MITM 解密，直接拒绝 TCP 连接；
即使 DNS 预解析在 VPN 隧道就绪前完成，连接仍会被路由层拒绝。

### 明确未做的改动

- **未添加任何 `,PROXY` 强制代理规则**：保持 v4.57 原路由行为，避免国内 App 主接口被强制走海外代理导致"无网络"；
- **未改动 [MITM] hostname 行**；
- **未改动** 闲鱼/酷安/微博 的现有 DIRECT 规则与其他所有节。

## 保留项（v4.57 原样）

- 全局 QUIC 阻断 `PROTOCOL,QUIC,REJECT`；
- v4.54 全局 URL-REGEX 请求级兜底；
- 闲鱼开屏接口 URL-REGEX 与素材域名拦截；
- 所有 URL Rewrite / Map Local / Body Rewrite / Script 规则。

## 升级建议

升级本版本后在 Shadowrocket 中重新勾选/刷新模块，然后强制关闭常用 App 进程冷启动测试。
若个别 App 第一次启动仍有开屏广告，请提供该 App 名称，以便针对性补充其广告SDK域名。
