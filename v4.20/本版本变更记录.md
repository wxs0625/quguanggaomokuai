# v4.20 - 基于 v4.7 恢复联网保留去广告版

- 日期：2026-08-13
- 文件夹：v4.20/
- 模块文件：v4.20/全能去广告修复版-Shadowrocket-v4.20.sgmodule
- 本次依据：用户确认 v4.7 “没有广告但没有网络”，v4.19 仍有开屏广告；因此本版不再沿用 v4.19 的广告 SDK 试验链路，回到 v4.7 无广告基线。
- 核心判断：v4.7 的无网络更可能来自把 api.huachenjie.com 下的业务数据接口返回空列表，而不是必须放开全部广告链路。

## 本版改动

- 保留 v4.7 的 api.huachenjie.com/run-front/ad 空响应，用于继续拦截闪动校园业务域广告接口。
- 保留 v4.7 的 ad.shunchangzhixing.com/getAd 空响应，并新增 ad.shunchangzhixing.com / report.shunchangzhixing.com 兜底拒绝规则。
- 禁用 v4.7 中 run-front/ai/getAICategory 和 run-front/home/sports/getPopup 的空列表替换，避免正常业务数据被当成无网络。
- 新增 api.huachenjie.com、oss-cdn.huachenjie.com、api-cfg.8ziben.com 直连规则，减少启动页等待和主业务加载失败。
- 保持 api.huachenjie.com 在 MITM hostname 中，用于继续命中 run-front/ad 路径级广告拦截。

## 已核对项

- 版本头已更新为 v4.20。
- v4.7 中两个疑似造成无网络的业务接口已注释，不再主动返回空列表。
- api.huachenjie.com/run-front/ad 仍保持启用。
- ad.shunchangzhixing.com/getAd 仍保持启用。
- 未继承 v4.19 顶部的广泛广告 SDK 直连/试验规则。

## 使用建议

- 先在 Shadowrocket 中完全替换为 v4.20 模块，再关闭并重新打开闪动校园。
- 如果仍显示旧广告，先清理闪动校园后台并等待缓存失效；开屏广告有可能来自 App 本地缓存。
- 如果 v4.20 仍出现无网络，再提供新 PacketTunnel 日志，需要进一步判断是否由 api.huachenjie.com 的 MITM 本身触发。
