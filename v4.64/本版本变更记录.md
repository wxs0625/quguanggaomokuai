# 全能去广告精简范围恢复版 v4.64 变更记录

- 基线版本：**v4.61**（按用户要求，不基于 v4.62/v4.63；v4.63 经比对为 v4.62 的内容克隆）
- 发布日期：2026-09-01
- 问题现象：安装 v4.61 后，**闲鱼冷启动仍有开屏广告**。用户提供了 Shadowrocket 流量日志（proxy-2026-09-01-072622.db）用于取证。

## 根因分析（流量日志实证）

### 1. 冷启动瞬间的闲鱼网关连接是「裸 IP 直连」

日志 `2026-09-01 07:26:28`（闲鱼冷启动 07:26:28–07:26:41，共 189 条记录）中，闲鱼网关的全部业务流量只以如下形态出现：

```
2026-09-01 07:26:28 | DIRECT | 203.119.238.121:443 || DOMAIN-SUFFIX,goofish.com,DIRECT
2026-09-01 07:26:28 | DIRECT | 59.82.9.30:443     || DOMAIN-SUFFIX,goofish.com,DIRECT
```

即目标是 **IP:443**，而非 `acs.m.goofish.com` 等域名。对比同一条日志中淘宝网关的连接：

```
2026-09-01 07:26:28 | DIRECT | https://acs.m.taobao.com/gw/mtop.common.getTimestamp/* || DOMAIN-SUFFIX,taobao.com,DIRECT
```

同一时刻、同样 DIRECT 路由，淘宝网关的完整 URL 可见（MITM 解密正常），**唯独闲鱼网关的 IP 直连不被解密**——证明问题不在 DIRECT 路由，而在「IP 形态的连接本身」。

### 2. IP 直连导致所有 URL 级拦截全部失明

Shadowrocket 的开屏拦截（[URL Rewrite]/[Map Local]/[Rule] URL-REGEX）都需要看到完整 URL。IP 直连连接不被 MITM 解密，URL 不可见，因此 v4.61 中针对闲鱼开屏的全部规则——

- `^https?:\/\/(g-)?acs\.m\.goofish\.com\/gw\/mtop\.taobao\.idlecommerce\.splash`（URL Rewrite 前缀兜底）
- `^https:\/\/acs\.m\.goofish\.com\/gw\/mtop\.taobao\.idlecommerce\.splash\.ads`（Map Local）
- [Rule] 段三条 `URL-REGEX ... REJECT-DICT`

——对冷启动流量**全部无法命中**，开屏广告直接放行。

### 3. 跨日志交叉验证（18 个日志库，2026-08-18 → 2026-09-01）

- 全部日志中从未捕获到闲鱼开屏端点（`splash`/`welcome`/`idlecommerce`）的完整 URL——因为它总是藏在 IP 直连里；
- 08-28 20:26 冷启动同样出现 4 个裸 IP 直连（`203.119.252.123`、`59.82.9.188`），与 09-01 的 `203.119.238.121`、`59.82.9.30` 合计 4 个；
- 08-28 15:57 热会话中大量 `g-acs.m.goofish.com`、`acs.m.goofish.com` 完整 URL 正常可见并被拦截——**证明域名连接路径下 MITM 与拦截规则完全可用**。问题仅存在于冷启动的 IP 直连。

### 4. 为什么会出现 IP 直连

模块已拦截闲鱼的 AMDC 调度：

```
07:26:28 | REJECT | http://59.82.113.219/amdc/mobileDispatch?appkey=12431167&v=6.5&appVersion=7.27.60&cv=1 || AND,((URL-REGEX,^http:\/\/.+\/amdc\/mobileDispatch),(USER-AGENT,%E9%97%B2%E9%B1%BC*)),REJECT
```

（该冷启动中共 5 次，含 `59.82.113.10`、`47.246.103.9`、`amdc.m.taobao.com`。）

AMDC（阿里 HTTPDNS 调度）被拦截后，闲鱼客户端回退到**本地缓存的 IP 池**，直接以 IP 建立 TLS 连接。这正是冷启动「必现」、热启动「正常」的差异来源：冷启动用缓存 IP，热会话走正常域名解析。

### 结论

**冷启动开屏广告的根因是：闲鱼以缓存 IP 直连网关，绕过了基于域名/URL 的全部拦截机制。**
与 v4.62/63 处理的哔哩哔哩问题无关，本版本不包含任何 B 站相关改动。

## 修复内容

### [Rule] 新增 4 条精准阻断（位于闲鱼广告素材域名拦截之后）

```
# v4.64 闲鱼冷启动：阻断 IP 直连通道，强制回退域名连接
IP-CIDR,203.119.238.121/32,REJECT,no-resolve
IP-CIDR,203.119.252.123/32,REJECT,no-resolve
IP-CIDR,59.82.9.30/32,REJECT,no-resolve
IP-CIDR,59.82.9.188/32,REJECT,no-resolve
```

机制说明：

1. **精准**：仅 4 个 `/32` 精确 IP，全部来自流量日志实证的闲鱼网关连接，不覆盖整个网段，不影响其他任何流量；
2. **强制回退域名连接**：阻断缓存 IP 后，闲鱼 mtop SDK 只能回退 DNS 解析，改连 `acs.m.goofish.com` / `g-acs.m.goofish.com` 域名。08-28 15:57 热会话已证明该路径下连接可被 MITM 解密、开屏接口可被现有规则拦截；
3. **机制先例**：与 v4.57 全局 QUIC REJECT「阻断无法解密的传输通道、强制回退到可解密通道」完全同构；[Rule] 优先级高于用户配置中的 `DOMAIN-SUFFIX,goofish.com,DIRECT`（模块规则先于用户规则求值），保证这 4 个 IP 必然命中；
4. **不强制代理**：闲鱼网关域名仍走 DIRECT（v4.61 现有行为不变），国内业务主接口不走海外代理，规避「无网络」风险。
