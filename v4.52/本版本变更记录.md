# v4.52 本版本变更记录

生成时间：2026-08-20

版本定位：基于 v4.51，为未被专用模块覆盖的软件增加全局开屏广告兜底处理。

## 问题背景

用户反馈很多软件首次启动会出现开屏广告，但后续启动不再出现。此类现象通常表示首次启动请求使用了未覆盖的接口，或者广告只在首次请求时下发并被应用保存。v4.51 已有多种专用处理方式，但没有统一覆盖未列出软件的明显开屏接口路径。

## 规则核对

v4.51 的开屏相关处理并非单一机制：既有 URL Rewrite 的拒绝，也有 Map Local 空 JSON，还有需要远程响应脚本处理的接口。直接把全部规则统一成拒绝或空响应会改变已正常联网软件的接口语义，因此本版采用低范围全局兜底。

全局规则只识别 URL 路径中明确出现以下开屏特征的请求：

- `splash`、`splash_config`、`splash_info`、`splash_screen`、`splash_ads`、`splashAd`
- `startup`、`startupAd`、`openscreen`、`open_screen`、`openScreen`、`openScreenAd`
- `startpicture`、`startpage_ad`、`startAd`、`openingBanner`
- `open_advertisement`、`app_open_screen_ad`、`appOpenScreen`
- `getAppStartAd`、`getAppSplash`、`getOpenscreenBanners`

## 本次处理

1. 新增一条全局 Map Local 兜底规则，匹配上述明确的开屏路径段。
2. 兜底响应返回 HTTP 200、`Content-Type: application/json` 和空 JSON `{}`，避免应用因连接失败回退到内置开屏广告。
3. 全局规则放在 Map Local 专用规则之后，已经有专用规则的软件优先使用原有精确响应。
4. 不匹配整个域名，不使用 `DOMAIN-KEYWORD`，不拦截普通首页、推荐、搜索和播放接口。
5. 保留 v4.51 的京东本地启动脚本、京东直连例外和纵横小说兼容规则。
6. 未新增 v4.7 全量软件范围，未修改 v4.51 及之前版本目录。

## 验证边界

- 已完成规则文本和配置段静态检查；当前环境没有 iPhone/Shadowrocket 实机，不能把本版描述为完成手机冷启动实测。
- Shadowrocket 的 HTTPS Map Local 需要主机已经在 MITM 列表中；本版没有加入 `hostname = *`，未纳入 MITM 的软件不会被强制解密处理。
- 全局规则对路径命名规范的软件有效；使用非标准路径或将广告内容放在普通启动配置接口中的软件，仍需要单独日志才能精确处理。
- 由于全局规则会对明确命名为 `startup` 的接口返回空 JSON，首次导入后应重点检查软件是否出现首页空白、无网络或启动卡住。
