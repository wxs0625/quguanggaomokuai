# v4.55 本版本变更记录

生成日期：2026-08-25

## 版本目的

修复多个软件开屏广告在 v4.54 修复后仍然间歇性复发的问题。通过闲鱼代理日志分析发现根因后，确认该问题**不限于闲鱼**，所有使用 QUIC 协议或被外部分流规则设为 DIRECT 的 App 都会绕过 MITM，导致依赖 MITM 的去广告规则全部失效。

## 根因分析

1. **QUIC 绕过 MITM**：Shadowrocket 无法解密 QUIC 协议流量。当 App 通过 QUIC 发起广告请求时，URL Rewrite、Map Local、Body Rewrite、Script 等 MITM 依赖规则全部失效。v4.54 仅有 Apple ASN 和小红书的 QUIC 阻断，大量主流 App 未覆盖。

2. **外部分流 DIRECT 绕过**：Shadowrocket 的外部分流规则集（如「国内直连」）将 `goofish.com` 等域名设为 DIRECT，流量不经代理，MITM 不解密，模块规则失效。此规则不在本模块任何版本中。

3. **idlecommerce.splash.ads 未出现在日志**：闲鱼开屏广告请求不在代理日志中，确认是通过 QUIC 绕过了代理。

### 2. 闲鱼请求级开屏广告拦截

- `URL-REGEX,"^https?:\/\/(g-)?acs\.m\.goofish\.com\/gw\/mtop\.taobao\.idlecommerce\.splash(?:\.ads)?(?:\/|\?|$)",REJECT-DICT`
- `URL-REGEX,"^https?:\/\/(g-)?acs\.m\.goofish\.com\/gw\/mtop\.taobao\.idle\.home\.splash",REJECT-DICT`
- `URL-REGEX,"^https?:\/\/acs\.m\.taobao\.com\/gw\/mtop\.taobao\.idlecommerce\.splash(?:\.ads)?(?:\/|\?|$)",REJECT-DICT`
- 在 QUIC 阻断 + MITM 生效后，这些规则能拦截闲鱼开屏广告接口
- 使用 REJECT-DICT 返回空 JSON `{}`，避免 App 弹出无网络提示

## 风险控制

- QUIC 阻断仅影响指定域名的 QUIC 协议流量，TCP/TLS 流量不受影响。
- 阻断 QUIC 后 App 自动回退到 TCP(TLS)，正常业务请求不受影响。
- 未使用全局 `PROTOCOL,QUIC,REJECT-DROP`，仅阻断有 MITM 规则的平台域名，避免影响其他无关服务。
- 请求级 URL-REGEX 规则使用 REJECT-DICT 返回空 JSON，而非完全丢弃。

## 用户侧建议

除了更新模块到 v4.55 外，建议检查 Shadowrocket 的分流传规则集，确保以下域名**不走 DIRECT**：
- `goofish.com`、`acs.m.goofish.com`、`g-acs.m.goofish.com`
- 其他有 MITM 规则的域名也应走代理
