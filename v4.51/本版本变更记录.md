# v4.51 本版本变更记录

生成时间：2026-08-20

版本定位：基于 v4.50，针对用户提供的京东日志修复启动业务误拦，并增强纵横小说开屏广告规则的 URL 兼容性。

## 日志核对

附件数据库为京东日志，共 331 条记录，时间范围为 09:32:44 至 09:33:27。京东启动和首页接口，包括 `start`、`welcomeHome`、`basicConfig` 与多个 `universalResourceDetail`，均显示为 `DIRECT`，没有发现京东主接口被拒绝。

日志中实际被拒绝的京东相关主机只有以下几类：

- `dns.jd.com:443`，命中 `DOMAIN,dns.jd.com,REJECT`，4 次。
- `policy.jd.com:443`，命中 `DOMAIN-SUFFIX,policy.jd.com,REJECT`，1 次。
- `im-x.jd.com:443`，命中 `DOMAIN,im-x.jd.com,REJECT`，2 次。
- 日志同时显示过旧配置中的 `jddebug.com` 和 `101.124.19.122` 拒绝记录。

其中 `dns.jd.com`、`im-x.jd.com` 和 IP 拒绝并不是 v4.50 当前集成文件中的完整业务配置，说明日志对应的 Shadowrocket 实际生效配置仍叠加了旧版京东独立模块或旧版本规则。v4.51 对这些主机增加了本模块内的直连优先项；使用时应只保留一个集成模块，避免旧独立京东模块再次覆盖。

## 本次处理

1. 在 `[Rule]` 最前面增加 `dns.jd.com`、`policy.jd.com` 和 `im-x.jd.com` 的 `DIRECT` 例外，避免启动所需服务被广告规则误拒绝。
2. 增加日志中出现的京东 IPv4 和 IPv6 地址直连例外，兼容旧配置残留的精确 IP 拒绝。
3. 移除 v4.50 集成文件中的 `policy.jd.com` 拒绝规则，避免同一文件内出现直连和拒绝冲突。
4. 将京东 `start` 响应从远程脚本中拆出，改用版本目录内的 `京东启动去广告.js`；保留原远程脚本处理其它京东接口。
5. 本地启动脚本仅处理 `start` 的 JSON 响应：清空 `images`，将 `showTimesDaily` 设为 0；空响应或非 JSON 响应保持原样，不生成伪造业务数据。
6. 纵横小说启动规则从固定的 `https://api1...` 扩展为所有 `http/https` 协议、查询参数和 `zongheng.com` 子域，并使用 `reject-200` 返回空的成功响应，降低启动页偶尔漏拦的概率。
7. 纵横小说礼包接口同步兼容查询参数和 `api`、`api1`、`api2` 主机，仍只处理礼包广告接口。
8. 未恢复 v4.7 全量模块，未新增未确认的软件模块；v4.50 及之前版本目录未修改。

## 使用与验证边界

- 导入 v4.51 后，应停用旧版 v4.49、v4.50 和单独的京东模块，避免同一请求同时存在旧拒绝规则。
- 规则静态检查确认京东启动脚本、京东直连例外和纵横兼容规则存在；当前环境没有 iPhone 和 Shadowrocket 实机，不能声称已经完成手机上的连续启动实测。
- 建议重新导入后清理京东和纵横小说缓存，各冷启动 5 次，并分别检查日志中 `dns.jd.com`、`policy.jd.com`、`im-x.jd.com` 是否为 `DIRECT`，以及纵横启动 URL 是否命中 `reject-200`。
